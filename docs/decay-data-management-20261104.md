# Decay 数据、来源与能级悬浮提示

本轮接入已核对的低能自发衰变事实，新增独立版本 `2026.11.04.1`。原子能量、寿命、矩阵元、HFS、Rabi公式及主图SVG布局保持原版；新增分支不参与耦合强度计算。

## 三层文件职责

| 位置 | 职责 | 发布到网页 |
|---|---|---|
|`data/decay.json`|显式采用的分支、误差、来源、理论/实验/近似/待核类型、适用条件及分母范围|是|
|`src/data/generated-decay.js`|由上一文件确定性生成的运行时副本；不手工编辑|是|
|`src/data/decay.js`|只读冻结API：`DECAY`、`DECAY_VERSION`、`getDecayRecord(levelId)`、`getDecaySource(id)`|是|
|`data/literature/decay-audit-2026-11-04/`|原文结构化事实、PDF指纹、候选值、级联人口、冲突及缺口；不自动采用|否|
|`references/decay-sources-20261104.json`|中央书目输入，含原件相对位置和访问状态|否|
|`references/decay-literature-queue-20261104.md`及JSON|真正需要手动取得的原文、优先级和核对用途|否|
|`references/papers/`|保留原始PDF，Git忽略，不重写现有文件|否|

`decayVersion`仅标识新增衰变数据。现有原子dataset和公式版本不因显示层增加事实而重写。旧跃迁presentation中的branching兼容文字不是新分支的事实入口；能级提示统一读取按上能级ID保存的独立记录，T6/T7共用6s7s ³S₁数据。

## 采用规则

³D₁的三条与³S₁的四条β保留原表数值和误差，包括³S₁→¹P₁=0.0021(9)。0.9999与1.0001是所引表格舍入和，不二次归一。它们是所引电子J级低能E1模型的理论分支，不提升为完整逐F/mF实验测量或全多极完备证明。

¹P₁回基态保留`1 − 6(4) × 10⁻⁸`互补表达式，避免百分数格式化成精确100%。³P₀/³P₁的近闭合模型保留空数值与近似表达式；³P₂按F保留来源独立的部分率，β仍待核；图内65S缺少匹配全部条件的完整首跳表，保持待核。基态是“不适用”，不是零分支。

部分率单独保存为`rateEvidence`，带s⁻¹单位、F条件与理论/实验分类。Xu的固态Ne测量经修正推断的自由原子HFI率不改称直接自由原子完整分支实测。不同模型的率不拼成共同分母；Senoo/Ma的级联终态、Wu的BBR模型及腔增强不进入当前65S的β。

## 悬浮提示

`diagram-details.js`在既有能级卡片内调用`renderDecayDetails`；`energy-diagram.js`和主图SVG保持字节不变。卡片保留悬浮、键盘及触屏触发，默认只显示必要数值、证据标签、J级范围和右上角来源小标。条件、原页、DOI和部分率默认折叠，展开时在原卡片内滚动，避免继续向屏幕外增长。

已登记DOI复用原有文献编号；独立新增来源在现有编号后编号，小标直接链接公开原文。完整来源与原文表位置同时保存在折叠内容。所有字符串转义，公开数据白名单拒绝本机路径、PDF全文与未知字段。

寿命行按现有上态寿命quantity绑定来源，能量行继续使用能量来源，避免³P₂的Mishra理论寿命被误标为Qiao能量文献；65S的旧标度寿命也保持其独立来源。该修正只调整来源小标，不改变寿命或能量数值。

验收触发需等待程序性滚动完成后再取焦，避免把原有“窗口滚动关闭悬浮框”行为当作新增数据错误；真实鼠标悬浮及手机触控另有测试。初次失败的配置与触发时序验收记录保留在本地证据包。

## 更新与检查

```sh
# 修改来源/采用事实前先核对原文与条件；只生成公开运行时副本。
npm run decay:export
npm run decay:validate

# 文献事实包只读核对，原件存在时检查SHA及字节。
node data/literature/decay-audit-2026-11-04/verify.mjs

# 全流程包括文献索引、衰变生成一致性、测试、构建和发布产物。
npm run check
npm run test:e2e
```

新论文应先登记书目、原件指纹和提取事实，再判断是否与目标态及环境匹配。下载成功、身份确认、数值核查和采用为模型输入是不同状态；用户手动下载原件应放入`references/papers/`后重新登记核查，不自动覆盖β。
